# Como contribuir

Obrigado pelo interesse. Este é um material de estudo, então toda correção,
melhoria de explicação ou diagrama mais claro é bem-vinda.

## O que cabe aqui

- Correção de erro técnico (um valor errado, uma explicação imprecisa).
- Melhoria de texto que deixe um ponto mais claro.
- Diagrama novo ou ajuste de um existente.
- Exemplo ou caso que ajude a entender um conceito.

## O que não cabe

- Pedido de ajuda para clonar credencial de terceiro sem autorização. O material é
  educativo e defensivo. Veja a seção "Uso responsável" do
  [README](README.md).
- Dumps, capturas ou arquivos com dados de credenciais reais. O `.gitignore` já
  bloqueia esses formatos de propósito. Não envie esse tipo de arquivo.

## Padrão do texto

Para manter a unidade do material:

- Sem emoji.
- Sem travessão (use vírgula, parênteses, dois-pontos ou ponto).
- Texto direto, sem floreio. Frase curta explica melhor que frase pomposa.
- Capítulos 01 a 09 não citam equipamento. Nomes de aparelhos ficam só no apêndice
  (capítulo 10).
- Português, com os termos técnicos em inglês quando for o uso corrente (UID, SAK,
  trailer).

## Padrão dos diagramas

- Os diagramas são feitos em Mermaid, dentro de blocos de código no próprio
  Markdown.
- Sem emoji nos rótulos.
- Rótulos curtos. Se precisar de duas linhas, use `<br/>`.
- Prefira acento só no texto corrido. Nos rótulos de diagrama, evite acento para
  não quebrar a renderização em alguns visualizadores.

## Como enviar

1. Faça um fork do repositório.
2. Crie um branch com um nome curto do que muda (ex.: `corrige-bcc-cap05`).
3. Faça commits pequenos e com mensagem clara, um assunto por commit.
4. Abra um Pull Request descrevendo o que mudou e por quê.

Para apontar um erro sem mexer no código, abra uma issue usando um dos modelos.
Qualquer dúvida, pode abrir uma issue também.
